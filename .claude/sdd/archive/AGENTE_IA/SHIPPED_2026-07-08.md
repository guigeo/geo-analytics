## Summary

Chat com agente de IA sobre o mapa: o usuário pergunta em português sobre os dados do
Censo 2022 (por município/setor) e o agente responde com números **sempre vindos de tools**
e pinta os resultados no próprio mapa. Primeiro componente server-side do projeto:
`web (React) → agent/ (FastAPI + SDK openai puro, function calling) → query/ (DuckDB)`.
Grounding por construção — os destaques do mapa saem deterministicamente das rows das
tools; o LLM só redige o texto. Validado por 31 testes offline + benchmark real de 16
casos (16/16, meta ≥14) com `gpt-5-mini`. Roda 100% local (`make dev-ia`); deploy na VPS
é a fase 2.1.

## Lessons Learned

### Process

- **Validar assumptions no /design pagou imediato:** a A-001 (pintura por código) derrubou
  a decisão nº 4 do brainstorm (`selection.ts` não serve — `queryRenderedFeatures` só vê o
  viewport) ANTES de virar retrabalho no build. Checar 2 arquivos custou minutos.
- **Benchmark comportamental (tool+args+destaques) > benchmark de valores:** expressar o
  esperado como comportamento tornou os 16 casos executáveis sem depender de números que
  mudariam com os dados — e pegou exatamente os defeitos certos no 1º run real.
- **O 1º run do benchmark falhou onde o offline não podia pegar:** os 3 fails eram de
  *comportamento do LLM* (recusa chamando tool; métricas cruas), invisíveis com client
  fake. Testes offline garantem o mecanismo; a régua com o LLM real valida a política.
- **E2E manual ainda achou coisa que a régua não pegou:** "Curitiba" pintava Curitibanos
  junto (`LIKE %nome%`). Assert de `contem_codigos` passava; o olho no mapa não.

### Technical

- **Grounding determinístico é a decisão mais valiosa do design:** derivar
  `destaques`/`dados` das rows das tools (última tool de dados vence) elimina alucinação
  de código IBGE por construção e dispensou structured output — menos um modo de falha.
- **Loop de tool-calling à mão é pequeno de verdade:** ~40 linhas legíveis com teto de
  iterações, autocorreção e trace. O aprendizado que motivou a Abordagem A se confirmou:
  não há mágica de framework que justifique a dependência neste escopo.
- **Erro de tool como payload (não exceção) habilita autocorreção barata:** devolver
  `{"erro": ..., "validas": [...]}` ao LLM corrigiu métrica inválida em 1 iteração nos
  testes; a política "2ª falha = mensagem amigável" limita custo.
- **Resolução nome→código precisa de match exato primeiro:** `LIKE '%nome%'` sozinho
  contamina os destaques (Curitiba+Curitibanos). Exato → fallback substring resolve sem
  perder a busca parcial.
- **System prompt é código de política:** duas frases ("fora de escopo = zero tool call";
  "traduza nomes de métricas") levaram o benchmark de 13/16 a 16/16 sem tocar em código.
- **Pydantic como fonte única por tool** (validação + JSON Schema via `model_json_schema()`
  + docstring = description) elimina drift entre schema e runtime.

### Communication

- A pergunta "qual modelo?" resolvida no /define (gpt-5-mini via `.env`) evitou re-discussão
  nas fases seguintes; deixar configurável tirou o peso da decisão.
- Documentar a revisão do brainstorm como ADR (com o porquê) mantém a trilha auditável —
  o brainstorm continua íntegro no arquivo, o DESIGN registra o que mudou e por quê.

### Tools & Libraries

- **SDK `openai` puro + Pydantic v2**: suficiente para 1 agente + 7 tools; portável p/ o trabalho.
- **DuckDB `strip_accents`**: busca por nome sem acento em SQL puro, sem dependência extra.
- **`pytest -m benchmark` + `addopts = "-m 'not benchmark'"`**: run padrão offline/grátis,
  régua real opt-in — bom padrão p/ qualquer projeto com testes que custam dinheiro.
- **Proxy do Vite** (3 linhas): matou CORS em dev e espelha o papel do Caddy na 2.1.

## Recommendations for Future Work

| Area | Recommendation |
|------|----------------|
| Fase 2.1 (deploy) | Parquets canônicos via `deploy.sh`; agente na VPS (systemd/container) + Caddy reverse-proxy `/api → :8000`; chave no `.env` do servidor |
| Latência | Se ~15–18 s incomodar no uso real: streaming SSE (corte YAGNI mais provável de voltar) ou trocar `OPENAI_MODEL` |
| Busca no header | Busca município/UF client-side (índice JSON gerado no ETL + `fitBounds`) — funciona no site estático hoje; caso perfeito p/ Dev Loop. Endereço = geocoder externo, decisão à parte |
| Novas perguntas | Se o uso real extrapolar as 7 tools: agregações por recorte antes de considerar `consulta_sql_avancada` (text-to-SQL guardado) |
| Conhecimento | `/distill AGENTE_IA`: loop de tool-calling puro, grounding determinístico e benchmark declarativo são KB generalizável (replicar no trabalho) |
